## ④ 在岗判定改"计划 + 签到"推导（完成）

行业主流是"当班医生 = 计划命中 + 已签到"（不把在岗状态写进排班表）。系统里 **biz_staff_attendance（实际出勤表）早已建好**（check_in/check_out/attendance_status/confirm_status，注释"闭环第3步：计划 vs 实际对照落点"），签到入口（checkIn/checkOut/markAbsent/adjust/confirm）也齐全——本轮把 onDutyAt 接到签到：

| 改动 | 文件 |
|---|---|
| `StaffScheduleVO` 加 `checkInTime`（HH:mm:ss）+ `actualOnDuty`（Boolean） | `vo/StaffScheduleVO.java` |
| 注入 `BizStaffAttendanceMapper`；`onDutyAt` 对命中行批量查签到（一次查防 N+1，重复签到取最早），`toOnDutyVO` 后回填两字段 | `service/impl/StaffScheduleServiceImpl.java` |
| 急诊当班取数：**已签到(actualOnDuty=true)优先，无人签到则回退计划**——未启用打卡的环境急诊接诊仍取得到人 | `appoint/service/impl/EmergencyServiceImpl.java` |

**行为变化**：有打卡 → 急诊派单/交班只认"已签到到岗"的医生；无打卡 → 行为与之前一致（计划在岗）。前端此刻在岗卡片可按 `actualOnDuty` 展示"已签到"标记（本轮未动展示，如需加可下轮补）。
