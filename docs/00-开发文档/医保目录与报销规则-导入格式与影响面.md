# 医保目录 / 报销规则 导入格式与影响面清单

> 适用：拿到省医保局下发的目录 Excel、待遇政策文件后，按本文格式灌进院内库。
> 代码侧改动见 271 增量；本文只讲**怎么导**和**导完影响哪些地方**。

## 一、先纠正三个会让人导错的前提

### 1. 险种键 = 患者主档原文，不是枚举名

`insurance_type` 存的是 `biz_patient.medical_insurance_type` 的**原文**：

| 主档实际取值 | dev 库人数 |
|---|---|
| 自费 | 104 |
| 城乡居民医保 | 43 |
| 城镇职工医保 | 39 |
| 公费医疗 | 4 |
| 商业医疗保险 | 1 |
| 超级长的历史脏值…（造数据） | 5 |

结算时 `SettlementBillServiceImpl.resolveInsurance` 传给 mapper 的就是这份原文。
**写成 `职工医保`（枚举名）= 规则永远不命中，且不报任何错**，只是悄悄退回 `byItemType` 硬推定。

### 2. 规则表四维，没有"医院级别"这一维

规则表 `biz_yb_catalog_rule` 的匹配键 = `item_code` + `catalog_type` + `encounter_type` + `insurance_type`。

湖南省待遇差异**是按医院级别分的**（职工住院：基层93% / 一级92% / 二级90% / 三级85%），
规则表表达不了这一维。本院是二级医疗机构，所以直接取二级档落值：

| 场景 | 起付线 | 支付比例 | 年度限额 |
|---|---|---|---|
| 职工门诊 | 50（每次，累计≤200） | 60% | 在职 1500 / 退休 2000 |
| 职工住院 | 800（首次，累计≤2000） | 在职 90% / 退休 92% | 15 万 |
| 居民门诊 | 0（限协议基层，70%） | 60%（二级档留档） | 420（长沙 560） |
| 居民住院 | 800 | 85% | 以医保局核定为准 |

> 如果将来要按级别分档，要么给规则表加一维，要么拆多条规则按机构切换——那是另一个轮次的事。

### 3. 年度限额跨单累计**没有实现**

规则表的 `deductible` / `ceiling` 是**行级配置**，不是累计器。
湖南的「每次起付 50、年度累计不超过 300」「年度最高支付限额 1500」需要**跨结算单的年度台账**，
现有表结构承载不了。当前把年度限额落成 `ceiling` 做单行上限兜底，**跨单那一半未实现**。

要真做，得先建年度累计台账（患者 × 结算年度 × 已用起付/已报统筹），另开轮次。
别把行级 `ceiling` 当年度累计器看。

## 二、两个导入接口

| 用途 | 接口 | 权限 | 幂等键 |
|---|---|---|---|
| 国家医保目录 | `POST /api/charge/ybCatalog/importBatch` | `finance:insuranceMapping:add` | `yb_code` |
| 报销规则 | `POST /api/charge/ybCatalogRule/importBatch` | `finance:insuranceMapping:edit` | `rule_no` |

两个都是**存在即更新**，重复导入不会产生重复行。

### 2.1 目录导入字段（`YbCatalogUpsertDTO`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `catalogType` | int | ✅ | 1-西药/中成药 2-中药饮片 3-医疗服务项目 4-医用耗材 |
| `ybCode` | string | ✅ | 国家医保编码，**全局唯一**，幂等键 |
| `ybName` | string | ✅ | 国家标准名 |
| `spec` / `unit` / `dosageForm` | string | | 规格 / 单位 / 剂型 |
| `insuranceLevel` | int | | 1-甲类 2-乙类 3-丙类 |
| `payRatio` | decimal | | 支付比例% |
| `effectiveDate` | string | | `yyyy-MM-dd` |
| `expireDate` | string | | `yyyy-MM-dd`，空=长期有效 |
| `status` | int | | 0-停用 1-启用 |
| `remark` | string | | **政策出处写这里** |

### 2.2 规则导入字段（`YbCatalogRuleImportDTO`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `ruleNo` | string | ✅ | `ICR` + `yyyyMMdd` + 5位数字。**不自动生成**——编号是政策批次标识，自动生成就查不出哪批政策导的 |
| `itemCode` | string | ✅ | **院内字典编码**，见下表 |
| `itemName` | string | | 项目名称（冗余展示） |
| `catalogType` | int | ✅ | 0-自费 1-甲类 2-乙类 3-丙类 |
| `encounterType` | int | ✅ | 1-门诊 2-住院 |
| `insuranceType` | string | | 主档原文；**留空 = 通用规则**（不限险种） |
| `selfPayRatio` | decimal | ✅ | 自付比例% 0-100（乙类先自付；甲类=0，丙类=100） |
| `deductible` | decimal | | 起付线元，0=无 |
| `ceiling` | decimal | | 封顶线元，0=不限 |
| `poolRatio` | decimal | ✅ | 统筹比例% 0-100，0=全自费 |
| `effectiveDate` | string | | `yyyy-MM-dd`，空取当天 |
| `expireDate` | string | | `yyyy-MM-dd`，空=长期 |
| `priority` | int | | 越小越优先，空取 0 |
| `remark` | string | | **政策出处写这里** |

**`itemCode` 必须来自院内字典**（不是国家医保编码）：

| 类别 | 字典表 | 编码字段 | 样例 |
|---|---|---|---|
| 药品 | `sys_drug` | `drug_code` | `DRUG0001`、`BP0007` |
| 诊疗项目 | `sys_treatment_item` | `item_code` | `TR001` |
| 检验项目 | `sys_laboratory_item` | `item_code` | `LB001` |
| 影像检查 | `sys_inspection_item` | `item_code` | `CT001` |

> 国家医保编码在 `biz_yb_catalog.yb_code`，两者通过 `biz_yb_mapping` 对照表连起来。
> 规则表认的是院内编码（结算时账单行 `item_code` 就是它）。

## 三、影响面清单

### 3.1 代码改动（271）

| 文件 | 改了什么 | 为什么 |
|---|---|---|
| `BizInsuranceCatalogRuleMapper` | `insurance_type` 匹配语义从「只认精确/只认 null」改成「精确优先、通用兜底」；排序加 `(insurance_type IS NULL) ASC`；删掉零引用的 `selectEffectiveRule` | 原来只要患者有医保号，全表通用规则一条不命中 |
| `SettlementBillServiceImpl` | 规则取用键从 `itemCode` 改成 `itemCode+catalogType`；`ceiling` 从整行清零改成裁剪；`deductible` 接进计算 | 原来同项目甲乙规则会串；起付线配了不生效；封顶线会少报 |
| `BizInsuranceCatalogRule`（实体） | `insuranceType` 注释改为主档原文口径 | 旧注释写「职工/居民/公费」，是坑的源头 |

### 3.2 新增

| 文件 | 作用 |
|---|---|
| `YbCatalogRuleImportDTO` / `YbCatalogRuleImportBatchDTO` | 规则导入入参（比例范围、编号格式、日期格式都收口） |
| `YbCatalogRuleService` / `YbCatalogRuleServiceImpl` | 规则批量导入（`rule_no` 幂等） |
| `YbCatalogRuleController` | `POST /api/charge/ybCatalogRule/importBatch` |

**规则表以前只能写 SQL 塞**，目录表却有导入接口 —— 这个不对称补上了。

### 3.3 数据改动

| 表 | 改了什么 |
|---|---|
| `biz_yb_catalog_rule` | 新增 15 条真政策规则；演示行保留不动（不再被精确档抢占，但未配精确险种时仍兜底） |
| `biz_yb_policy` | **收敛**：城镇职工医保/2 原来 6 行并存（60/80/85/88/92），而 `findPolicy` 用 `LIMIT 1` 恒读到 id=1 那条 85% → 停用重复行，一险种一档 |

### 3.4 不在本轮范围（明确留白）

| 项 | 原因 |
|---|---|
| 湖南目录全量导入 | 需要医保局下发的真实文件，不是手写能补的 |
| 年度累计台账（起付/限额） | 要新建跨单台账表 + 结算时读写，是独立轮次 |
| 医院级别维度 | 规则表四维装不下，见 §1.2 |
| 在职/退休分档 | 主档无独立取值（都填"城镇职工医保"），要区分得先给主档加参保身份字段 |
| `limit_flags` 限制标志 | 表里有字段、代码里没读。适应症/急诊/慢病备案限制要接医嘱和慢病备案才能判 |

## 五、模板

`workspace/yb_import_template.json` 是可直接粘的请求体样例，
生成脚本 `workspace/_gen_yb_import_template.cjs`。

Excel 转 JSON 时注意：

- 日期列是**字符串** `yyyy-MM-dd`，不是 Excel 日期序列号
- `payRatio` / `selfPayRatio` / `poolRatio` / `deductible` / `ceiling` 是**数字**，不是带 `%` 或 `¥` 的字符串
- 空值传 `""` 或省略，不要传 `null` 字符串
- 一行错一个维度就多报/少报统筹，导完务必跑一遍验收脚本
