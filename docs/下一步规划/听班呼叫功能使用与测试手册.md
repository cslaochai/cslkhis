# 听班呼叫功能 · 使用与测试手册

> 功能：临床二/三线值班医生的**听班呼叫 → 到岗应答 → 超时升级**闭环
> 增量脚本：`docs/03-增量SQL变更/297-临床值班听班呼叫链路.sql`（已在 dev 库执行完毕，无需再跑）

---

## 0. 一句话理解这个功能

急诊/临床一线遇到搞不定的病人，需要上级医生到场。**听班**＝二线/三线医生不在医院、
在家待命（`attend_mode=2`）。这个功能就是：**呼叫他 → 他应答到岗 → 他不接就自动往上升级**。

以前只有 `attend_mode` 这个标记（说"这个人是听班的"），现在补上了完整链路，
**谁被叫了、多久没来、谁升级的，全有记录**。

## 2. 手工测试（浏览器点一遍，5 分钟）

### 准备两个浏览器（或两个无痕窗口）

| 角色 | 账号 | 密码 | 今晚排的是 |
|---|---|---|---|
| 呼叫方（管理员/医务科） | `admin` | `123456` | —— |
| 被叫方（二线医生） | `chenjianan` | `123456` | 呼吸内科**二线**夜班（陈建安） |
| 被叫方（三线医生） | `luochaoyang` | `123456` | 呼吸内科**三线**夜班（罗朝阳） |

### 步骤 1 —— 发起呼叫

1. `admin` 登录 → 左侧「**排班值守中心**」→「**听班呼叫**」
2. 点右上「**发起呼叫**」
3. 弹框里：
   - 呼叫科室：选 **呼吸内科**
   - 值班日期：今天
   - 班次：选 **夜班**
   - 被叫层级：选 **二线**
   - **看"当班听班人"这一行** —— 应该显示 `二线 · 陈建安（13787166898）`
     👉 **这是关键**：它证明系统是从排班解析出"今晚二线是谁"，不是你自己挑的人
   - 患者姓名：`测试患者`（选填）
   - 患者位置：`呼吸内科 3 床`（选填）
   - 呼叫事由：`患者突发胸闷血氧下降，一线处理后仍不缓解，需二线到场指导`（**必填**）
   - 到岗时限：`10`（分钟）
4. 点「**发出呼叫**」→ 提示"呼叫已发出"，弹框关闭，表格出现一条新记录，状态 **待到岗**

### 步骤 2 —— 被叫人收到通知并应答

1. 切到 `chenjianan` 的窗口 → 右上角**消息待办**红点 / 侧栏「消息待办」
2. 应该看到一条 **「听班呼叫」** 类型的待办（内容含呼叫事由 + 限 10 分钟到岗）
3. 两种方式应答：
   - **方式 A**：在「听班呼叫」页把「视角」选成「**待我到岗**」→ 找到那条 → 点「**到岗应答**」→ 确认
   - **方式 B**：在**消息待办**里找到那条「听班呼叫」→ 点「**处理**」→ 弹框里有呼叫单详情 +「**到岗应答**」按钮 → 点它
4. 应答后：状态变 **已到岗**，到岗时间落库，消息待办的"待处理"标记消失

> ⚠️ 消息中心点「处理」**不是**只标已读 —— 弹框里会直接给出「到岗应答」按钮，点完呼叫单真的闭环。
> （这条是后修的缺陷：以前点「处理」只把消息标已读，呼叫单还停在「待到岗」，医生以为应答了其实没应答。）

### 步骤 3 —— 看呼叫流水

点该行的「**详情**」→ 弹框里能看到完整时间线：

```
发起呼叫      2026-10-26 11:45:00   待到岗
到岗应答      2026-10-26 11:45:50   已到岗
```

### 步骤 4 —— 测超时升级（最关键的一环）

**A. 想快速看到效果**：发起呼叫时把「到岗时限」改成 **1** 分钟，然后**放着别应答**。
1 分钟后定时任务（每分钟扫一次）会自动升级；也可以点页面右上「**补跑超时升级**」立刻触发。

升级后你会看到：
- 状态变 **已超时升级**
- 被叫人从「二线 · 陈建安」变成「**三线 · 罗朝阳**」
- 流水多一条：`超时升级   10 分钟未到岗，升级至 三线 罗朝阳`
- `luochaoyang` 收到一条 **「听班呼叫超时升级」** 类型的 urgent 消息
- **陈建安（二线）的待办变成「已关闭」**（不是"已处理"）—— 他没到岗，不能标成处理过
- **罗朝阳（三线）仍可应答**：他在听班呼叫页或消息中心都能点「到岗应答」，倒计时从升级时刻重新算

**B. 验证幂等**：再点一次「补跑超时升级」→ 提示"已升级 **0** 条"，流水**不会**多一条
（升级标记 `escalate_status` 落了库，不会重复轰炸）。

## 4. 手工验证数据库（想自己查的时候）

```sql
-- 呼叫单（状态机 + 升级标记）
SELECT id, call_no, duty_date, shift_type, dept_name, target_level, target_emp_name,
       call_time, arrive_time, status, escalate_status, escalate_time, escalate_from_level
FROM biz_duty_call ORDER BY id DESC LIMIT 10;

-- 呼叫流水（每次状态流转一条，只增不改）
SELECT call_no, action_type, action_time, from_status, to_status, operator_name, action_note
FROM biz_duty_call_log ORDER BY id DESC LIMIT 20;

-- 今晚各科室的二/三线听班人（呼叫目标人就是从这里解析的）
SELECT d.dept_name, p.duty_level, p.post_name, r.employee_name, r.shift_type, r.duty_date
FROM biz_duty_roster r
JOIN biz_duty_post p ON p.id = r.post_id
LEFT JOIN sys_department d ON d.id = p.org_id
WHERE r.del_flag = 0 AND p.duty_scope = 6 AND p.duty_level IN (2,3)
  AND r.duty_date = CURDATE()
ORDER BY d.dept_name, p.duty_level, r.shift_type;
```

**状态码对照**（`biz_duty_call.status`）：

| 值 | 含义 | 何时变成 |
|---|---|---|
| 0 | 待到岗 | 发起呼叫 |
| 1 | 已到岗 | 被叫人应答 |
| 2 | 已超时升级 | 到岗时限内没人应答，升级到上一层级（**仍可应答** —— 当前被叫人接手的就是它） |
| 3 | 已取消 | 发起人主动撤销 |

**升级阶梯**：二线 → 三线 → 全院总值班（行政协调线）。都叫不到就停在「已超时升级」并记"需医务科介入"。

## 5. 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 菜单里找不到「听班呼叫」 | 菜单/授权缓存没刷 | 退出重登；或清 Redis `his:perm:role:*` + `his:user:identity:*` |
| 医生角色进不去 `/duty-call` | 缺祖先目录 2945 授权 | 跑 297 脚本的授权段 |
| 发起呼叫报"没有排 X 听班值班人" | 该科室该班次没排班 | 到「排班值守中心 → 全院总值班」页切「**科室医师值班**」排班；或换别的科室/班次 |
| 弹框里"当班听班人"显示"未排班" | 选了白班但只有夜班排了 | 班次切「夜班」 |
| 接口 404 | 后端还是旧 jar | 重新构建并重启后端 |
| 改了代码但页面没变 | 前端 HMR 失效 | 刷新页面；或重启 vite |
| 管理员调接口 403 | admin 是显式授权制 | 跑 297 脚本授权段（含 admin） |
| 消息中心点「处理」没反应 | 前端缓存了旧版弹框 | 刷新页面（Ctrl+F5 强刷） |
| 升级后没人能应答 | 旧版缺陷，已修 | 确认前后端都重启到最新 |

## 6. 调参数

**到岗时限**（默认 10 分钟）：

```sql
UPDATE sys_config SET config_value = '15' WHERE config_key = 'duty.call.timeout_minutes';
```

改完立即生效（后端每次读库，不缓存）。

**想看某科室今晚谁值班**：去「排班值守中心 → 全院总值班」，把「值班种类」切成「**科室医师值班**」。

## 7. 边界说明（别误解功能范围）

- **被叫人不能由呼叫方指定**：系统只叫"这一班的那个听班医生"。这是刻意的 ——
  能挑人，值班制度就废了。
- **一线不能被叫**：一线是留院值班（人就在科室），只有二线/三线是听班。
- **节假日**：按日期排班已能表达"某天谁值班"，呼叫链路按日期取数，节假日自动适用。
  但**没有独立的节假日日历表**（库里无节假日主数据源），"节假日当天自动排班"是另一个缺口。
- **呼叫单不联动排班表**：呼叫是运行时事件，**排班事实仍在 `biz_schedule`/`biz_duty_roster`**，
  两者分开，避免把"谁在班"和"谁被叫过"搅在一起。
