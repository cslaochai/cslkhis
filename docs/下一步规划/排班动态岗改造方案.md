# 排班动态岗改造方案（下一步规划）

> 背景：门诊/排班域当前把"员工—部门—角色—岗位"和"排班"拆成标准 RBAC 多表，但**同一张 `sys_employee_post` 被当成两种语义在用**——静态岗（收费员/行政/编码/药学）它确实是事实，动态岗（医生/护士/医技）它只是"执业资格池"，当天位置应由排班决定。下游却一刀切把"主岗科室"当"当前在岗科室"，导致动态岗（尤其分诊护士）打开分诊台时科室/权限错乱。
>
> 本文档给出局部改造方案，**不动** RBAC 主体与排班录入/审核权限（`staff:schedule:*`），只补"静态/动态"标识与"动态岗当前位置推导"。

---

## 一、现状盘点（字段级证据）

| 环节 | 表 / 文件 | 现状 | 判定 |
|---|---|---|---|
| 员工→角色×科室岗位 | `sys_employee_post`（`EmployeePostServiceImpl`） | `(employeeId, roleId, deptId, isPrimary, effectiveDate, expireDate)` | ✅ 标准资格注册表 |
| 排班↔岗位绑定 | `biz_schedule.employeePostId` | `resolvePost()` 强制排班必须落到本人名下一条已存在 post，否则报"还没有分配岗位" | ✅ 已绑，非脱钩 |
| 当前位置取数 | `EmployeePostServiceImpl.syncPrimaryDept` / `switchPost` | 主岗 `deptId` 回填 `sys_employee.dept_id` 并写进 token | ⚠️ 对静态岗对、对动态岗错 |
| 分诊台/工位 | `biz_opd_station`（无 `dept_id`）、`biz_opd_station_assignment`（无 `employee_post_id`） | 全院公共工位，不挂科室；派岗只带 `employeeId+shiftId` | ❌ 游离在岗位×科室体系外 |
| 静态/动态标识 | 角色 `staffType`（1医生2护理3医技4药学5收费6行政其他） | 仅粗分类，**未声明排班行为** | ❌ 缺显式标识位 |

---

## 二、核心结论

1. **"给医生护士分配科室+岗位是假的"表述不准确**：`sys_employee_post` 对动态岗不是假数据，是**执业资格池（能力声明）**；真正当天事实在 `biz_schedule`。排班已正确引用岗位，未脱钩。
2. **真问题**：模型缺"静态/动态岗"标识，且下游把静态逻辑（主岗=当前位置）套到动态岗身上。
3. **全动态是伪前提**：收费/行政/编码天生固定在岗，硬设动态=每天排废班。应**两类共存 + 下游正确区分**。

---

## 三、改造项（按优先级）

### P0 — 角色加 `scheduling_mode` 标识
- `sys_role` 增列 `scheduling_mode`（`0=静态`/`1=动态`，默认按 `staffType` 推导：收费/行政/编码/药学=静态，医生/护理/医技=动态）。
- 含义：静态岗的 `deptId` 即事实位置；动态岗的事实位置改由"当日已发布排班"反推。

### P1 — 动态岗"当前位置"改从当日排班推导
- 新增 `CurrentStationResolver`：给定 `employeeId + 今天`，优先取 `biz_schedule` 中 `publishStatus ∈ {已发布,已变更}` 且 `dutyStatus=上班` 的行 → 其 `deptId`/`stationId` 作为"当前在岗位置"。
- 登录落点 `resolvePrimaryPost`、token 写入、前端 `getUserInfo().deptId` 默认值：动态岗一律走 `CurrentStationResolver`，静态岗维持原主岗逻辑。
- 影响面：`EmployeePostServiceImpl`、鉴权 token、`TriageView.loadDepts`、各工作站"当前科室"默认值。

### P2 — 分诊台/工位接入岗位×科室体系
- `biz_opd_station` 增 `served_dept_ids`（覆盖科室集合，兼容"大科统管"与"专科独立"两种粒度）。
- `biz_opd_station_assignment` 增 `employee_post_id`（派岗时从 `biz_schedule` 行带过来，取代只取 `staffType`）。
- `TriageView` 按"派岗 `employeePostId` → 绑定分诊台 → `served_dept_ids`"自动带出科室范围，**禁用手动自由切诊区**（至多允许在覆盖范围内切）。

### P3 — 排班录入/审核 RBAC（保持不变，仅记录）
- 录入/提交：`staff:schedule:add`；修改/换班/撤回：`staff:schedule:edit`；删除：`staff:schedule:delete`。
- 审核发布/驳回：`staff:schedule:audit`，且须命中 `sys_department` 三类审核人（门诊/护理/全院岗位排班审核人）；管理员 10012 全局豁免。
- 排班员概念已存在（`OpdAssignVO.派岗方式=1排班员指定`），无需新建。

---

## 四、验证口径（交付前必跑）

1. 动态岗护士登录 → token `deptId` = 当日排班科室，而非注册主岗科室。
2. 静态岗（收费员）登录 → `deptId` 仍为主岗科室，行为不变。
3. 分诊护士派岗到分诊台 → 打开分诊台自动带出 `served_dept_ids` 范围，无法切到无关科室。
4. 回归：排班录入/审核权限、切换岗位、号源诊室绑定不受影响。

---

## 五、不在本次范围

- RBAC 主体表结构重构（已是标准多表，无需重写）。
- 收费/行政/编码等静态岗的动态化（明确不需要）。
- 聚合支付网关真通道、长处方医生站 UI、M2 床旁结算（见总进度）。
