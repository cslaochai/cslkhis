# 门诊医保实时结算改造计划

> 目标：把"出账时院内估算统筹"改成"收款时实时调医保平台 2201/2301 拿真实 splits"，对齐标准 HIS 门诊收费时序。

---

## 1. 现状诊断

| 环节 | 现状 | 问题 |
|---|---|---|
| 出账时 `pool_amount` | `computePoolFromRule` 按院内规则表比例硬算 | 院内拍数，不是医保平台返回的真实统筹 |
| 出账时 `account_amount` | 写死 `BigDecimal.ZERO` | ✅ 正确（占位） |
| 出账时 `self_amount` | `amount - pool` | 跟着 pool 一起假 |
| 收款时 | QrPayDialog 只有现金/扫码两档 | 没刷社保卡、没扣个账 |
| `biz_payment_txn` | 从来没有 `pay_method=4` 的流水 | 个账从来没真扣过 |
| 医保清单 `preSettlement` | 从账单 pool 列反推 splits | 数是假的 |
| 通道层 `preSettle/formalSettle` | 接口 + remote/mock 实现已写 | 孤岛，没 Controller 调 |
| csmis 侧 2201/2301 | 已写完编译通过 | 待 HIS 侧接通 |

**核心病灶**：现在的"医保"是个事后报盘壳子——出账时按院内规则拍个统筹数，收款时只收现金/扫码，收完钱再组 2304 报文发给医保局要钱。患者从来没刷过社保卡、个账从来没真扣过。

---

## 2. 目标时序（标准 HIS 门诊结算）

```
收费员出账（L2）
  ↓
pool=0 / account=0 / self=全额（占位，院内不再估算统筹）
  ↓
患者来交钱 → 点「收款」→ QrPayDialog
  ↓
问：是否使用医保？
  ├─ 否 → 直接出码/收现金，金额=应缴全额（自费患者路径不变）
  └─ 是 → 刷医保码/输身份证
            ↓
         ① 调 /charge/insurance/preSettle（HIS 后端 → mss /gateway/2201）
            ↓
         返回 splits：统筹 X / 个账 Y / 自付 Z
            ↓
         收费员跟患者念数、患者确认
            ↓
         ② 调 /charge/insurance/formalSettle（HIS 后端 → mss /gateway/2301）
            ↓
         mss 当场扣个账 Y、出 YBZ 单号
            ↓
         HIS 同事务：
           - 落 biz_payment_txn（pay_method=4, amount=Y, direction=1）
           - 回写 biz_settlement_bill：pool=X / account=Y / self=Z
           - 回写 biz_settlement_bill_item：行级 splits（按比例分摊）
            ↓
         剩余 cashPay=Z 怎么收？
            ├─ 现金
            └─ 出聚合码（金额=Z，不是全额！）
            ↓
         付清 → 出票
```

## 3. 改造步骤（按依赖顺序）

### Step 1：出账时不再院内估算统筹

**文件**：`SettlementBillServiceImpl.java`
- `buildItems`（约 695 行）：删掉 `computePoolFromRule` 调用，`poolAmount` 直接置 `BigDecimal.ZERO`
- `accountAmount` 已经是 0，不动
- `selfAmount = amount - pool = amount`（因为 pool=0）
- 同步删掉 `computePoolFromRule` / `computePool` / `ruleByItem` 等只服务于院内估算的私有方法（如果没别的地方用）
- `resolveInsurance` 保留：还是要调 `checkInsured` 查参保，决定这单是不是医保患者（covered=true 才在收款时显示"医保个账"档）

**影响**：
- 出账后账单上 pool=0、account=0、self=全额
- 只有收款时调了 2201/2301 才会回写真实 splits
- 自费患者（未参保/未带社保卡）路径完全不变，还是收全额

### Step 2：HIS 后端新建实时结算 Controller

**新文件**：`charge/controller/InsuranceRealTimeSettleController.java`
- `POST /charge/insurance/preSettle?billId=xxx`
  - 从 billId 查账单 + 账单行 + 患者
  - 组 `SettleRequest`（tradeNo=账单号+时间戳、idCard、insuranceNo、items）
  - 调 `InsuranceChannelService.preSettle`
  - 返回 splits 给前端展示（不落库）
- `POST /charge/insurance/formalSettle?billId=xxx`
  - 同样组 `SettleRequest`（tradeNo 用跟 preSettle 同一个，幂等）
  - 调 `InsuranceChannelService.formalSettle`
  - 成功后**同事务**：
    1. 落 `biz_payment_txn`（pay_method=4, direction=1, amount=personalAccount, channel_txn_no=receiptNo）
    2. UPDATE `biz_settlement_bill`：pool_amount / account_amount / self_amount
    3. UPDATE `biz_settlement_bill_item`：行级 splits（按行金额占比分摊，因为 mss 返回的是整单 splits）
  - 返回 splits + receiptNo 给前端

**注意**：
- 权限码：`finance:insurance:edit`（跟现有医保结算页一致）
- 账单状态守卫：只能对"待支付/部分支付"的账单调
- 幂等：同一个 billId 的 2301 只能成功一次（重复调直接返回上次结果）

### Step 3：QrPayDialog 前端加"医保个账"档

**文件**：`front/src/components/his/QrPayDialog.vue`
- 弹层结构改造：
  - 第一步：显示患者信息 + 问"是否使用医保"（只对医保患者显示这个选项）
  - 选"医保个账"→ 调 preSettle 接口 → 显示 splits 卡片（统筹/个账/自付三段）
  - 患者确认 → 调 formalSettle → 显示"个账已扣 Y 元，剩余 Z 元请选择支付方式"
  - 剩余 Z 元再选现金/扫码（聚合码金额=Z）
- 自费患者路径不变

### Step 4：医保清单模块改口径

**文件**：`InsuranceSettlementServiceImpl.java`
- `computeFund` 方法（653 行）：不再从"院内 pool 列 + 已收流水"反推
- 改为：从 `biz_settlement_bill` 上已经被 2301 回写的真实 pool/account/self 取数
- `generateFromBill`：出账时 pool=0 就不再生成清单（现在的逻辑是 pool>0 才生成），改成"2301 成功后"才生成清单（在 formalSettle 里调）

### Step 5：联调验证

- 起 csmis 8090 + HIS 后端 + 前端

  - 查 `biz_payment_txn` 有 pay_method=4 流水
  - 查 `biz_settlement_bill` 的 pool/account/self 是真实值
  - 查 csmis `mss_settlement` 表有结算单

## 4. 不做的事

- 不接微信/支付宝医保移动支付（一码付）：那是另外一个项目，需要微信商户号 + 医保中台对接，本期不做
- 不做住院医保结算：本期只做门诊
- 不做行级 splits 精确分解：mss 返回整单 splits，HIS 侧按行金额占比分摊（发票列印够用，对账以整单为准）
- 不改 2304/2305 报盘流程：报盘还是从回写后的账单取数，流程不变
