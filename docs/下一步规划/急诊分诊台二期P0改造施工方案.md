# 急诊分诊台二期 P0 改造施工方案

> 依据：一期已闭环「MEWS 评分 + 动态复评」（接口 26/26 + UI 17/17 通过）。
> 本方案只解决**预检分诊台本身**的简陋问题（P0 四项），抢救/留观区护理执行（出入量、静脉通路、机械通气）不在此列，属另一岗位页面。
> 真实 HIS 口径来源：中国三级医院急诊医学科信息系统建设指南（cem.org.cn）、护理信息系统功能指南（ttbz.org.cn）、绍兴妇幼/淮安一院/襄阳一院/北京四季青急诊信息化招标文件。

## 一、现状核查（代码全貌，开工前已探明）

后端**零改动**即可支撑四项能力，全部字段/接口已存在：

| 能力所需 | 后端支撑 | 落库时机 |
|---|---|---|
| 三区分区 | `biz_emergency.zone`（String，红/黄/绿），`EmergencyZoneEnum.ofTriageLevel` 推导 | 登记时 `register()` 写 `setZone(getZoneByLevel(level))` |
| 时间轴节点 | VO 暴露：`createTime`(登记) / `admissionTime`(入抢救室) / `diagnosisTime`(接诊) / `observationStartTime·EndTime`(留观) / `finishTime`(转归) | 各动作时点写（接诊 469 行、入抢 256 行） |
| MEWS 趋势 | `GET /emergency/reevalList` 返回每次复评的 `mewsScore + createTime` + 当前 `mewsScore` | 复评流水表一期已建 |
| 一键转归 | `POST /emergency/updateStatus`（`EmergencyStatusUpsertDTO`，已含留观占床、终态拦截、转住院拦截走 admit） | 已实现 |

**结论**：P0 四项纯前端改造，不动后端、不动表结构、不新增接口。

## 二、改造项

### P0-1 三区看板 / 卡片模式
- **改**：`source/front/src/views/emergency/EmergencyView.vue`
- **做**：顶部加「看板 / 列表」视图切换（默认**看板**，对标招标"默认卡片模式"）。看板按 `zone` 分三个区块（红区 / 黄区 / 绿区），区块内按 `triageLevel` 升序（I 级置顶）。每张卡片着色（红区深红边、黄区琥珀边、绿区绿边），展示：患者姓名/性别/年龄、急诊号、分级徽章 + MEWS、主诉（truncate）、状态、入急诊时长（now - createTime）、待复评/超时标记、操作按钮（复评 / 转归 / 详情）。
- **依据**：绍兴妇幼、北京四季青招标"列表、床卡两种展现模式，可分区显示患者，默认卡片模式"。
- **不动**：现有列表视图保留为第二 tab，统计卡、筛选、待复评逻辑全部复用。

### P0-2 就诊时间轴
- **改**：新建 `EmergencyTimeline.vue`（卡片展开 / 详情组件内嵌），`EmergencyView.vue` 卡片点击展开调用。
- **做**：横向时间线，节点 = 登记 → 入抢救室 → 接诊 → 留观(起~止) → 转归；缺失节点灰色显式标注"未记录"。时长标注（如"候诊 90min"）。
- **依据**：淮安一院招标"以时间轴展示病人分诊、入科、检验检查开立、会诊申请、转区等关键医疗行为"。

### P0-3 MEWS 趋势图
- **改**：新建 `EmergencyMewsTrend.vue`，复用 `reevalList` 接口。
- **做**：折线图，x = 时间（登记点 + 各次复评点），y = MEWS 分数（0-14），标注当前分；分数 ≥9 红色段、5-8 琥珀、<5 绿。卡片/详情内嵌。
- **依据**：淮安一院"对危急值、化验、检查单能够提供趋势图"；建设指南"根据生命体征恶化自动触发警报，升级分诊等级"。

### P0-4 一键转归
- **改**：新建 `EmergencyTransferEdit.vue`，`EmergencyView.vue` 卡片「转归」按钮触发。
- **做**：弹框选择目标状态（诊治中 / 留观 / 离院 / 死亡；转住院走既有 `admit` 入口）。留观需选病区+床位（复用 `wardSelectList` / `bedSelectList`）。调既有 `updateStatus`。
- **依据**：襄阳一院/淮安一院"一键式病人转归，抢救区、留观区、EICU 顺畅流转信息自动记录，并提醒对应接收区域"。
- **不动**：既有 `EmergencyAdmitEdit`（入抢救室）、`EmergencyObsEdit`、`EmergencyHandoverEdit` 保留，转归面板只做状态切换的统一入口。

### 顺带纠正一处真实 HIS 口径（权限）
- 分诊护士（role_id=9 / role_code=10020）一期仅授 role 1/8 的「急诊工作站-修改」(菜单 2011, perm `opd.emergency:edit`)，导致护士在分诊台看不到「转归」入口——但真实 HIS 里分诊台护士正是患者流转（转归/留观/离院/死亡）的主操作人。已补授 role 9 → 菜单 2011。
- **踩坑**：`sys_role_menu.id` 是 bigint NOT NULL 主键无默认值，原 `INSERT IGNORE (role_id, menu_id)` 被 IGNORE 静默吞掉 "Field 'id' doesn't have a default value"，行始终写不进去。修正为显式给 `id = MAX(id)+1`，唯一键 `uk_role_menu(role_id, menu_id)` 保证幂等。`his:perm:role:10020` 当时无缓存（TTL 10min 已过期），后端下次解析自动回源新权限，无需手动清缓存。

### 顺带纠正一处测试夹具脏数据（非产品 bug）
- B7 转归失败根因：`EmergencyServiceImpl.syncAppointAndQueue` 在终态流转时按 `findEmergencyAppoint(patient_id)` 取急诊号挂号单、再按 `regist_id` 取队列，要求队列处于候诊/就诊中（守卫下沉到 WHERE，0 行命中抛"该队列状态已变更，请刷新后重试"）。看板夹具原复用 `patient_id=1`（陈张伟），该患者库里有一条 2026-10-20 的**终态急诊号队列**，导致守卫失败。夹具改专属 `patient_id`（8966 保留段，无任何挂号/队列）后 `findEmergencyAppoint` 返回 null、守卫整段跳过，转归只改急诊状态即成功。
